### 1.1 False-green fixes applied after the first Test CR

1. **UI-001..005**: the `ui/package.json` capability shortcut and all
   `expect(true)` placeholders are gone. The contracts now mount the REAL WebUI
   through `ui/test-support/index.ts` (renderApp/seedApiState) and assert
   user-observable behavior (§13); creating an empty `ui/` skeleton cannot
   turn them green.
2. **CFG-001/CFG-004**: mutation children now complete their READ phase
   before signaling readiness (`spawn-mutation.ts`), forcing deterministic
   overlap of mutation windows and giving CFG-004 a genuine stale-snapshot
   actor (a whole-config stale write-back now loses B and fails).
3. **SEC-004**: session/CSRF/Origin are probed as independent variables, all
   with a VALID Origin, so an Origin-only implementation cannot pass.
   **SEC-007** additionally asserts state unchanged after the oversized-body
   rejection.
4. **Isolated product environment** (`tests/v0.3/helpers/isolated-env.ts`):
   every Control Runtime / `start` / E2E / credential test runs against a
   temporary HOME, config, control state, runtime state, test adapters
   (secret/startup/tunnel/browser), and asserts the real user state root is
   never touched.
5. **L4 E2E now drives the product surface**: package → `start`/runtime →
   HTTP Control API (session+CSRF+Origin) → HTTP MCP client → runtime state.
   Application-service calls are not accepted as E2E evidence. E2E-001 runs a
   real `npm pack` → clean install → installed-bin spawn from a cwd outside
   the repository.
6. **GATE-B-3** now sets the literal secret VALUE into the referenced env var
   and asserts the value (not the env name) never appears in output, while
   argv carries only `env:WL_GATE_B_RUNTIME_KEY`.
7. **GATE-C-1** no longer auto-passes when the adapter module appears: it
   runs real feasibility assertions (Node 24 engine, declared store
   dependency, adapter instantiation) once `secret-store.ts` exists, and
   before that it fails RED carrying the BLOCKED evidence.
   **GATE-C-3** uses a deterministically injected unavailable platform seam.
8. **SECRET-001** performs credential setup through the real Control API into
   an isolated product state root and scans every persisted artifact for the
   sentinel. **APP-004** proves enable actually revalidates the root
   (enable with a missing root must reject or stay disabled).
9. **GATE-A-2** compares against the real `workspace-lens serve` stdio child
   process instead of an in-memory transport.

### 1.2 Fixes applied after the second Test CR (494b9db round)

1. **UI harness ownership**: the production-owned `ui/test-support` contract
   is gone. The tests mount the REAL root component `ui/src/App` directly
   (`tests/v0.3/helpers/render-ui.ts`: Testing Library render + fake Control
   API at the fetch layer). A fake `renderApp()` adapter can no longer
   satisfy the UI contracts because the component under test is the same
   module the product entry renders. **UI-002** now asserts
   `queryByText(/chatgpt\s+connected/i)` is `null` (text-node assertion, not
   a String()ified element); **UI-005** asserts the CURRENT setup stage is
   Tunnel via the accessibility marker (`aria-current="step"`) and that
   exactly one stage is marked active.
2. **E2E-001 proves startup instead of printed output**: after installing
   and spawning the real bin, the test probes `GET /healthz` (200),
   `GET /` (200 + HTML) and requires `/mcp` to exist (non-404).
3. **Leak-proof runtime lifecycle for all start/control tests**: product
   flows run in a DEDICATED child process (`tests/v0.3/helpers/
   spawn-product-child.ts`) with a stop protocol — SIGTERM → child stops its
   runtime → the runtime's port must DRAIN before the temp state is removed;
   a still-open port fails the contract. START-001 stops both invocations.
4. **Stronger isolation**: child processes get HOME, XDG_CONFIG_HOME,
   XDG_DATA_HOME, XDG_STATE_HOME and WORKSPACE_LENS_CONFIG pointed at the
   temp state root, and Secret/Startup/Tunnel dependencies are injected as
   adapter OBJECTS from the tests (`tests/v0.3/helpers/test-adapters.ts`) —
   production "test"/"stub" mode strings are no longer part of the contract.
5. **CFG-004 deterministic seam**: the mutation layer must accept an
   optional `syncPoints.afterLoad(config)` callback (in-lock, after load,
   before apply). The CFG-004 child asserts its in-lock base state already
   contains B; a stale snapshot fails the child. CFG-001's concurrent
   overlap remains scheduler-dependent (documented); the deterministic
   lost-update window is covered by CFG-004's seam scenario.
6. **GATE-C-1** now requires a concretely declared OS credential dependency
   (allowlist: `keytar` / `@github/keytar`); an in-memory Map SecretStore
   with no OS dependency cannot pass the gate.
7. **E2E-003** requires a non-empty runtime identity
   (`typeof pid === "number"`), so an implementation without a test
   observable cannot pass.
8. **HTTP-002** now accepts BOTH contract-legal outcomes (reuse the healthy
   runtime or an explicit rejection) and in both cases asserts exactly one
   healthy manager remains.
