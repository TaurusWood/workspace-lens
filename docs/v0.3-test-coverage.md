## 13. Contract deviations and notes for reviewers

1. **GATE-B-2 (real evidence):** `tunnel-client runtimes status/stop` for a
   missing alias emit human-readable stderr with exit 1 rather than JSON even
   under `--json`. The v0.3 adapter must classify that state via exit code +
   error text, or upstream must confirm a JSON error shape. Frozen in
   `tests/v0.3/fixtures/gate-b/`. This does not invalidate the RFC, but the
   adapter contract (CONN-001/003) encodes it explicitly.
2. **GATE-B success-path lifecycle JSON** requires real provider credentials;
   the capture script freezes fixtures when a credentialed machine is
   available. A stub alone does not satisfy Gate B (§7 GATE-B-4).
3. **GATE-C-1** is BLOCKED by dependency-selection policy (no candidate
   OS-credential library is accepted yet); no plaintext fallback exists.
4. **Expected module names** in RED tests follow the implementation plan's
   target layout (`§2`); if a slice lands under a different name, update the
   path in `tests/v0.3/helpers/expected-module.ts` — Contract IDs and
   behavioral assertions stay authoritative.
5. **No production code changed** in this phase. New npm scripts
   (`test:v0.3`, `test:v0.3:watch`) and the vitest config split are
   test-infrastructure only; `npm test` remains the v0.2 regression gate.
