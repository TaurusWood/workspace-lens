# WorkspaceLens v0.2 Security Contract

Status: Normative security delta for v0.2.

This document extends `docs/security-model.md` for historical Git inspection. All v0.1 security invariants remain in force.

## 1. Security Objective

v0.2 adds visibility into local Git history without widening WorkspaceLens into a generic Git execution interface and without allowing historical content to bypass the existing workspace authorization or sensitive-path policy.

The critical invariant is:

> If a path is not allowed through the WorkspaceLens content policy, its historical Git representation is not an alternate read channel.

## 2. Historical AccessPolicy Invariant

`git_commit` and `git_compare` are content-bearing tools and MUST use the same `AccessPolicy` decision layer as `read_file`, `search_workspace`, and `git_diff`.

The policy applies to repository-relative paths mapped back into the authorized workspace, including files that:

- exist now;
- existed only in historical commits;
- were deleted;
- were renamed;
- were copied;
- are outside an authorized workspace when the workspace root is a subdirectory of a larger Git repository.

Blocked paths MUST NOT disclose:

- historical file contents;
- diff hunks;
- blocked path names through content-bearing results.

A redacted file count MAY be returned.

## 3. Historical Path Cases

Implementations MUST handle both sides of rename/copy/delete operations conservatively.

For a diff entry with old path and new path:

- if either relevant path maps outside the authorized workspace, content for that outside path must not cross the boundary;
- if either path is sensitive/blocked, the entry must be redacted unless the implementation can prove the returned portion contains only an independently allowed path and no blocked path disclosure;
- v0.2 SHOULD prefer full-entry redaction for sensitive rename/copy transitions rather than introduce complex partial disclosure logic.

Required security fixtures include:

```text
blocked file added historically
blocked file modified historically
blocked file deleted historically
allowed -> blocked rename
blocked -> allowed rename
workspace-subdirectory commit touching sibling repository paths
```

## 4. Revision Validation Invariant

Caller revision fields are data, not Git syntax fragments.

The public API MUST reject general revision expressions and option-like values as defined in `v0.2-mcp-tools-contract.md`.

Accepted revision input MUST be resolved through a fixed internal operation to a concrete commit SHA before subsequent history/diff operations.

The implementation MUST NOT pass caller input as:

- a command name;
- an option/flag;
- a revision range;
- a pathspec expression;
- a shell fragment;
- an environment override.

## 5. Git Execution Invariant

The existing Git process hardening remains mandatory:

- direct process spawn with `shell: false` or equivalent;
- fixed executable;
- fixed command templates;
- authorized workspace-derived working directory;
- no arbitrary caller-provided args;
- no interactive prompts;
- no pager;
- no external diff helper;
- no textconv for diff-producing operations;
- `GIT_OPTIONAL_LOCKS=0` or equivalent inspection-safe behavior where already used;
- no remote mutation;
- no workspace mutation.

Repository-controlled configuration is untrusted. The historical tools MUST NOT allow repository config to trigger an executable diff/text-conversion path.

## 6. Data Minimization

`git_history` intentionally returns commit metadata only and does not enumerate changed file paths in v0.2.

`git_commit` and `git_compare` return only policy-allowed diff content and policy-allowed file counts plus a redacted count.

Commit messages are untrusted repository data. They MAY contain prompt-injection-like text and must be treated as data by tool descriptions/hosts.

No tool should return author email by default in v0.2 because it is unnecessary for the review objective.

## 7. Output Bounds

All potentially large historical results MUST be server bounded.

- history count has a hard server maximum;
- commit/compare diff bytes reuse or obey the central Git diff payload ceiling;
- successful partial results explicitly report truncation;
- the caller cannot disable or raise server hard limits.

## 8. Error Disclosure

Historical Git errors MUST be normalized into stable WorkspaceLens errors.

MCP-visible errors MUST NOT include:

- raw Git command lines;
- shell strings;
- environment variables;
- unrelated absolute filesystem paths;
- stack traces.

## 9. Mandatory v0.2 Security Acceptance

Automated tests MUST demonstrate at minimum:

1. `HEAD~1`, `HEAD^`, `main..HEAD`, `@{upstream}`, `HEAD:path`, and option-like revision values are rejected before historical inspection runs;
2. a normal branch name, tag, full SHA, abbreviated SHA, and `HEAD` can resolve where present;
3. a historical `.env` add/modify/delete cannot leak path/body through `git_commit` or `git_compare`;
4. rename/copy transitions involving a blocked path do not leak the blocked path/body;
5. a workspace that is a subdirectory of a larger repository cannot expose sibling paths changed by the same commit;
6. large historical diffs are bounded and explicitly truncated;
7. repository-local diff/textconv configuration cannot execute an external program;
8. no new MCP schema accepts `command`, `args`, arbitrary Git flags, or shell fragments;
9. all operations remain read-only and leave the Git working tree/index unchanged.
