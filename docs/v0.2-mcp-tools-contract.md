# WorkspaceLens v0.2 MCP Tools Contract

Status: Normative v0.2 delta to `docs/mcp-tools-spec.md`.

This document defines the three MCP tools added in v0.2. Existing v0.1 tool semantics remain unchanged.

Before v0.2 release, the consolidated public tool specification may absorb this delta into `mcp-tools-spec.md`; until then this document is authoritative for these three tools.

## 1. Tool Surface

v0.2 adds exactly:

```text
git_history
git_commit
git_compare
```

The complete v0.2 public surface therefore contains ten semantic read tools.

No generic `git`, `git_command`, `shell`, `exec`, `args`, or command-passthrough tool is introduced.

## 2. Common Revision Type

A revision input identifies a commitish that WorkspaceLens resolves to exactly one commit before performing the requested operation.

Recommended public constraints:

```text
Type: string
Length: 1..200
Allowed character class: ASCII letters, digits, `.`, `_`, `/`, `-`
```

Additional semantic validation MUST reject at minimum:

- leading `-`;
- `..` anywhere;
- `@{` anywhere;
- trailing `/`;
- doubled `//`;
- values ending in `.lock`;
- any `~`, `^`, `:`, `@`, backslash, whitespace, shell metacharacter, or control character.

`HEAD` is explicitly allowed.

Accepted input examples:

```text
HEAD
main
feature/foo
v0.2.0
832de4f
832de4f8b6d3...
```

Rejected examples:

```text
HEAD~3
HEAD^
main..HEAD
main...HEAD
@{upstream}
HEAD:src/index.ts
:/pattern
--all
```

Resolution MUST occur through a fixed internal Git template and MUST yield a commit object. Tags may therefore resolve to their target commit where Git normally permits it.

After resolution, subsequent Git operations SHOULD use the resolved full commit SHA rather than the original caller string.

Unknown or non-commit revisions fail with `GIT_REVISION_NOT_FOUND`.

## 3. Additional Error Codes

| Code | Meaning | Retryable |
| --- | --- | --- |
| `GIT_REVISION_NOT_FOUND` | Accepted revision syntax did not resolve to a commit | No |
| `GIT_NO_MERGE_BASE` | `merge_base` comparison has no merge base | No |

Existing `INVALID_ARGUMENT`, `NOT_A_GIT_REPOSITORY`, `GIT_OPERATION_FAILED`, workspace errors, and internal errors continue to apply.

Errors MUST NOT disclose raw Git command lines, unrelated absolute paths, environment variables, or stack traces.

## 4. `git_history`

### Purpose

Return recent commit metadata from a validated start commit.

### Input

```json
{
  "workspace_id": "workspace-lens",
  "start": "HEAD",
  "max_commits": 20
}
```

Fields:

| Field | Required | Type | Default | Contract |
| --- | --- | --- | --- | --- |
| `workspace_id` | Yes | string | - | Existing authorized workspace ID |
| `start` | No | revision | `HEAD` | Validated commitish |
| `max_commits` | No | integer | `20` | `1..100`; server hard ceiling still applies |

Unknown properties MUST be rejected.

### Success output

```json
{
  "ok": true,
  "data": {
    "workspace_id": "workspace-lens",
    "start": "2b1f...",
    "commits": [
      {
        "commit": "2b1f...",
        "parents": ["87ad..."],
        "subject": "Add comparison support",
        "author_name": "Example Developer",
        "committed_at": "2026-09-05T12:34:56Z"
      }
    ],
    "truncated": false
  }
}
```

Requirements:

- `start` in output is the resolved full commit SHA;
- commit order is newest-to-oldest following normal Git history order from the resolved start;
- no commit body, changed filenames, patches, raw decoration, or arbitrary formatting are part of v0.2;
- `truncated` is true when more commits are available than the returned bounded result.

`git_history` is metadata-only and therefore does not enumerate historical paths.

## 5. `git_commit`

### Purpose

Inspect one commit and its bounded, policy-filtered change relative to the contract-defined comparison base.

### Input

```json
{
  "workspace_id": "workspace-lens",
  "revision": "HEAD"
}
```

Unknown properties MUST be rejected.

### Comparison base

The implementation resolves `revision` to commit `C`.

- if `C` has one or more parents, comparison base is the first parent `P1`;
- if `C` has no parents, comparison base is Git's empty tree;
- merge commits are therefore reviewed as `P1 -> C` in v0.2.

### Success output

```json
{
  "ok": true,
  "data": {
    "workspace_id": "workspace-lens",
    "commit": "2b1f...",
    "parents": ["87ad..."],
    "subject": "Add comparison support",
    "author_name": "Example Developer",
    "committed_at": "2026-09-05T12:34:56Z",
    "comparison_base": "87ad...",
    "files_changed": 3,
    "redacted_files": 1,
    "diff": "diff --git ...",
    "truncated": false
  }
}
```

For a root commit, `comparison_base` MUST be `null` and the diff semantics are empty-tree -> commit.

Requirements:

- `files_changed` counts returned/allowed changed files, not blocked files;
- `redacted_files` counts policy-blocked changed files without returning blocked paths;
- diff paths must be workspace-relative;
- repository changes outside an authorized workspace subdirectory must not be returned;
- blocked historical paths must not have their names or bodies returned;
- diff output reuses the server Git diff byte ceiling unless the central limits contract is explicitly revised;
- partial diff output sets `truncated: true`.

## 6. `git_compare`

### Purpose

Compare two validated committed revisions for implementation review.

### Input

```json
{
  "workspace_id": "workspace-lens",
  "base": "main",
  "head": "HEAD",
  "mode": "merge_base"
}
```

Fields:

| Field | Required | Type | Default | Contract |
| --- | --- | --- | --- | --- |
| `workspace_id` | Yes | string | - | Existing authorized workspace ID |
| `base` | Yes | revision | - | Validated commitish |
| `head` | No | revision | `HEAD` | Validated commitish |
| `mode` | No | enum | `direct` | `direct` or `merge_base` |

Unknown properties MUST be rejected.

### Semantics

Resolve caller inputs first:

```text
base -> B
head -> H
```

For `direct`:

```text
comparison_base = B
diff B -> H
```

For `merge_base`:

```text
M = merge-base(B, H)
comparison_base = M
diff M -> H
```

If no merge base exists, return `GIT_NO_MERGE_BASE`.

### Success output

```json
{
  "ok": true,
  "data": {
    "workspace_id": "workspace-lens",
    "mode": "merge_base",
    "requested_base": "c1a2...",
    "head": "2b1f...",
    "comparison_base": "8d4e...",
    "files_changed": 5,
    "redacted_files": 0,
    "diff": "diff --git ...",
    "truncated": false
  }
}
```

All SHA fields in successful output are resolved full commit SHAs.

Requirements:

- the comparison excludes staged, unstaged, and untracked working-tree state;
- the same historical AccessPolicy rules as `git_commit` apply;
- repository paths outside an authorized workspace subdirectory are omitted;
- output is bounded and explicitly truncated;
- same resolved base/head is a valid empty comparison and returns an empty diff rather than an error.

## 7. Git Process Contract

All three tools MUST use controlled Git execution only.

The implementation MUST preserve the existing adapter rules:

- WorkspaceLens chooses the `git` executable;
- `cwd` derives only from an authorized workspace;
- arguments come from fixed templates plus validated typed values;
- no shell is used;
- pagers are disabled;
- interactive prompting is disabled;
- external diff execution is disabled for diff-producing operations;
- textconv is disabled for diff-producing operations;
- repository hooks are not intentionally invoked;
- callers cannot provide Git flags or environment overrides.

## 8. Cross-Tool Review Model

The tools intentionally remain composable rather than introducing a `git_review_everything` operation.

Typical review flow:

```text
git_history
  -> git_compare(base, HEAD)
  -> git_status
  -> git_diff
  -> read_file / search_workspace
```

Committed state and working-tree state remain distinct facts.
